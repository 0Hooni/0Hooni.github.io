# 사용자 선호

블로그 글 작성 시 반영해야 할 사용자 개인 선호다.

## 글 구성

- 서론에 목차나 흐름표를 넣지 않는다. Chirpy의 사이드바 TOC가 대신한다. 서론에는 동기와 글의 의도만 짧게 적고 연결 문장으로 첫 본문 섹션에 이어간다.
- 별도의 최종 요약 섹션을 만들지 않는다. 본문이 충분하면 반복 요약은 불필요하다.
- 섹션 헤더는 번호 대신 이모지를 사용한다. 예: `## 🧭 제목`
- 서론 끝과 각 섹션 끝에는 다음 섹션으로 자연스럽게 이어지는 한두 문장을 둔다.

## 표와 단락 사용 기준

- 표는 셀 내용이 짧고 한눈에 비교할 수 있을 때만 사용한다.
- 한 셀에 한 문장 이상의 설명이 필요하면 표 대신 굵은 제목과 본문 단락으로 푼다.
- 오해와 실제처럼 긴 설명이 필요한 비교는 표보다 단락이 읽기 쉽다.

## 다이어그램

- ASCII 정렬이 깨질 수 있는 박스, 화살표, 흐름, 타임라인은 Mermaid를 사용한다.
- 한 줄짜리 단순한 박스나 타임라인은 일반 텍스트로 표현해도 된다.

## 입문자 대상 글의 톤

- React나 React Native 고유 개념을 설명 없이 전제하지 않는다.
- TypeScript 개념은 Swift의 대응 개념과 연결하면 이해하기 쉽다.
- React Hook 학습은 React Native 맥락으로 설명하고 DOM이나 웹 예시는 사용하지 않는다.
- 추상 개념은 일상 비유로 먼저 감을 잡게 한다.

## 글의 동기

- 서론의 작성 동기는 사용자의 실제 동기를 반영한다.
- 기술의 일반적인 효용을 동기로 대신하지 않는다.
- 회사의 React Native 브라운필드 파운데이션 같은 구체적인 학습 맥락을 사용한다.
